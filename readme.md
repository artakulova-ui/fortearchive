# FORTE / ARCHIVE — Project README

## 1. Обзор проекта (Project Overview)

**FORTE / ARCHIVE** (`fortearchive.com`) — независимый маркетплейс винтажной и архивной одежды с фокусом на Cop Copine и редкие дизайнерские вещи. Сайт сочетает минималистичный визуальный стиль, фильтрацию по категориям, модальные карточки товаров и галереи изображений.

Проект использует HTML, CSS и Vanilla JavaScript без тяжёлых фронтенд-фреймворков. Каталог загружается из Google Firebase Cloud Firestore.

## 2. Архитектура и стек технологий

- **Frontend:** HTML5, CSS3 и Vanilla JavaScript (`index.html`, `styles.css`, `script.js`).
- **Backend / Database:** Google Firebase Cloud Firestore.
- **Hosting:** Netlify с собственным доменом `fortearchive.com`.
- **Product images:** файлы хранятся в репозитории в `/images/` и доступны через `https://fortearchive.com/images/...`.

## 3. Структура данных в Cloud Firestore

Каталог хранится в коллекции **`items`**. Документ товара использует следующие поля:

| Поле | Тип | Описание | Пример |
| :--- | :--- | :--- | :--- |
| `title` | `string` | Полное наименование товара | `Cop Copine Archival Graphic Mesh Top` |
| `category` | `string` | Категория для фильтрации | `tops`, `jackets`, `dresses`, `skirts`, `trousers` |
| `code` | `string` | Внутренний артикул товара | `12163` |
| `status` | `string` | Наличие товара | `In Stock` или `Sold Out` |
| `stock` | `number` | Количество единиц в наличии | `1` |
| `size` | `string` | Размер или параметры | `2 (S / M)` |
| `description` | `string` | Описание и состояние винтажной вещи | `Archival semi-sheer mesh long sleeve top...` |
| `images` | `array<string>` | До 10 URL фотографий | `https://fortearchive.com/images/item_12163.jpg` |

## 4. Правила для разработки и наполнения каталога

### 4.1. Firestore

- Целевая коллекция — исключительно **`items`**.
- Фотографии хранятся в поле **`images`** типа массив строк; одиночное поле `image` не используется.
- Вместо цен указываются `status` (`In Stock` / `Sold Out`) и `stock`.
- Значения полей проверяются на соответствие схеме перед добавлением товара.

### 4.2. Медиафайлы

- Используйте прямые абсолютные URL своего домена вида `https://fortearchive.com/images/filename.jpg`.
- Не используйте Markdown-ссылки или сторонние фотохостинги для фотографий каталога.
- Файлы изображений должны находиться в `/images/`, а имена файлов и URL в Firestore должны совпадать.

### 4.3. Описания и интерфейс

- Пишите описания товаров на английском языке в стиле премиальных архивных платформ: указывайте материалы, особенности кроя, эстетику бренда и состояние вещи.
- Сохраняйте минималистичный дизайн и визуальную эстетику FORTE.
- Не добавляйте ценники: интерфейс показывает статус наличия и количество.

## 5. Локальный запуск и развертывание

1. Клонируйте репозиторий или откройте папку проекта.
2. Убедитесь, что изображения присутствуют в `/images/` и пути к ним совпадают с URL в Firestore.
3. Для локального тестирования запускайте сайт через HTTP-сервер, например расширение Live Server в VS Code. Не открывайте `index.html` через `file://`: это может мешать сетевым запросам Firebase.
4. Публикация на продакшен выполняется через развертывание проекта на Netlify.

## 6. Протокол отладки и предотвращения рекурсивных ошибок

### 6.1. Не повторяйте неудачные гипотезы

- Ведите историю попыток в рамках задачи: если исправление не устранило ошибку, не предлагайте тот же код повторно без новых данных.
- Не возвращайтесь к уже проверенному состоянию без объяснения, что изменилось в гипотезе.

### 6.2. Диагностика перед изменениями

Перед изменением `script.js` или конфигурации Firebase:

1. Сначала изучите точную ошибку в Console и вкладке Network браузерных DevTools.
2. Определите категорию проблемы:
   - **Firebase Rules / CORS:** например, `permission-denied`, CORS-блокировка или запуск через `file://`.
   - **Data mismatch:** несовпадение схемы Firestore, отсутствующие поля или значения `null`.
   - **DOM / Event Logic:** ошибки JavaScript при поиске элементов или обработке событий.

### 6.3. Если ошибка повторяется

1. Остановите повторение аналогичных правок.
2. Проверьте окружение: используется ли `http://localhost` или Live Server, сохранён ли файл и опубликованы ли актуальные правила Firebase.
3. Сформулируйте альтернативную гипотезу и проверьте её минимальным изменением, например безопасной проверкой `product.images?.[0]` с подходящим резервным значением.
4. Исправляйте проблему небольшими атомарными шагами и проверяйте каждый шаг до продолжения.
